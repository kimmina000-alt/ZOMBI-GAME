# 02. 투척·전투 시스템

## 원본 참고와 독자 구현
두 Roblox 플레이 영상에서 확인한 것으로 정리된 요소: 세로 투척 타이밍 바, '탭하여 던지세요' 안내, 물체 추적 카메라, 비행 거리와 배율 1.08x/3.86x 등, 직선형 하부 수집 지형. 정확한 원본 물리·배율 수식은 알 수 없으므로 재현 목표는 조작 경험이며 코드/에셋은 독자적으로 만든다.

## 입력 상태
Idle → OnPad → ChargingTiming(세로 바 왕복) → Release → ProjectileFlight(CameraFollow) → Impact/Explosion → Result → Cooldown → OnPad/Idle.
- 진입 즉시 GUI 생성/표시. 발판 외부로 나가거나 사망하면 정리.
- PC 클릭/키와 모바일 탭 모두 같은 서버 요청 인터페이스. 터치 다중 실행 방지.
- 기본 무기 돌멩이. 추후 그물 선택 및 무기 제작대 기능 해금.
- 강도·속도·궤적·최대 거리·Zone 도달 가능성은 공유 Config로 관리.
- 카메라 추적은 클라이언트 전용이며 캐릭터 사망·목표 소멸·시간 초과에 정상 원복.

## 돌멩이
- 돌을 던져 하부 착탄 시 **폭발**. 소리, 파편, 먼지, 충격파 VFX.
- 최근 요청은 **착탄 Zone 내 존재하는 좀비 전부 처치**. 이는 초기 아케이드 게임성 기준이며 원거리 사냥 난이도를 고려해 이후 반경·공격력·등급 제한으로 단계 업그레이드하는 안을 비교.
- 최초 충돌은 서버 레이캐스트/권한 있는 물리 검증. 발판 투명 경계는 돌을 막지 않도록 충돌 그룹 구분. 다른 Zone과 생존자·기지·플레이어는 피해 제외.
- 처치 기록, 코인 +15/XP +25는 **기존 과거 서버 코드의 기본 값**으로 보고됨. 레벨별 보상값은 후속 설정화. 다중 폭발이나 중복 이벤트 보상 방지.

## 그물
- 돌과 동일한 게이지/비행·카메라 파이프라인.
- 적중 Zone/범위의 포획 가능 좀비를 기절 또는 그물로 묶음. 기절 만료/재적중 처리.
- 수용소 해금 여부와 여유 슬롯, 대상 등급/레벨을 서버가 확인. 구체적인 포획 대상 선택·성공 확률은 설계 조정 필요.
- 그물 기절·포획은 돌 처치 보상과 별도 이벤트. 중복 처치 보상 금지.

## 기존 코드 통합
과거 조사: `CombatClient`가 `Remotes.AttackRequest`를 기다리고, 해당 RemoteEvent를 생성하는 비활성 `ServerScriptService.Services.ZombieSystemServer`가 있었음. 해당 서버를 복구·확장하는 편이 합리적. 한 개의 전투 authority, 하나의 좀비 스폰 루프. 서버와 클라이언트의 Remote 이름을 통일하며 기존 F키/모바일 입력을 망가뜨리지 않는다.

## 테스트 수락 기준
발판 진입 즉시 게이지 표시, 모바일 터치 조작, 바의 값과 실제 비행 일치, 투사체가 안전 벽에 막히지 않음, 정확한 Zone 판별, 폭발 시 생존자 무피해, 사망·리스폰 뒤 UI 복구, 다른 플레이어 공격 보상 절도 불가.
